# Git_Avto (бывший GIT_Automation / AutoSync) — обзор проекта

Живой документ (`Рабочая_Документация\Обзор.md`, стандарт 0.0.2). Обновлён чатом GIT_Automation
(Git_Avto) д15 (24.10.2026). Дни — от Дня 0 = 09.10.2026; события до него — обычными датами.

## Что это

Python-программа (tkinter, без консоли — `Сам_проект\AutoSync.pyw`) для автоматической
git-синхронизации: следит за файлами репозиториев, сама коммитит и пушит, спрашивает пользователя
только при расхождениях. Версия — git-тег «свободный префикс + номер пуша»; ветка и тег пушатся
одной атомарной командой.

С д14 — модуль **Git_Avto** будущей программы **Оператор_Проводника** (Operator_Conductor), см.
`План_архитектуры.md`. Разработку Оператора_Проводника координирует чат «Оператор_Operator_Conductor»
(передача дел — `Уведомление_для_Operator_Conductor_д14.md` в корне проекта); модуль Git_Avto ведёт
чат GIT_Automation. Прежние названия AutoSync и GIT_Automation заменяются на Git_Avto (объём замены
уточняется).

## Что принято

1. **Взаимная блокировка — главная причина «нет автопуша».** `RepoWatcher._lock` был `Lock`, а
   `sverka_versiy` вызывает сама себя, держа его; репозиторий вставал после первого успешного пуша
   (GIT_Automation 25.09 с 20:44, Power_struggle 25.09 с 19:41). Исправлено: `RLock`.
2. **Пуш.** Текст ошибки git всегда в журнале; номер тега +1 — только если тег уже есть на git; тег
   только на компьютере — «Проблема», номер не двигается; обрыв связи — 3 повтора того же тега
   (пауза 10 с); прочие отказы — «Проблема» без повторов. Локальные коммиты, которых нет на git,
   отправляются (раньше висели с «пуш не нужен»).
3. **Правило «Проблема».** Проверка не прошла (нет связи, отказ пуша, ошибка коммита, зависание) →
   таймер и слежение репозитория стоят, строка оранжевая, клик — причина и «Повторить проверку».
   Занятая проверка пишет «Проверка пропущена: идёт с …, этап …».
4. **Окно не зависает** при добавлении и редактировании репозитория (watchdog — в фоне).
5. **Первый запуск без `config.json`:** файл создаётся без сталкеров, подсказка в журнале, сразу
   открывается форма добавления.
6. **Расхождение ветки слежения** (вместо молчаливого `git checkout`, из-за которого 25.09 откатилась
   Power_struggle): окно «на диске ветка X, следим за Y» с тегами и «+» на кнопках —
   «Оставить X» (меняется ветка слежения в `config.json` и `.autosync_data`) или «Перейти на Y»
   (без замены файлов на диске, дальше сверка версий).
7. **Расхождение версий одной ветки:** версия с диска есть на git и своих изменений нет → вопрос
   «Обновить до актуальной?»; иначе три варианта с тегами — «Взять всё с git» (свои коммиты → ветка
   `autosync-backup/...`, незакоммиченное → `git stash`), «Отправить нашу версию как основную»
   (новый коммит поверх git, без force-push; файлы, которых нет на диске, из новой версии
   удаляются, в истории остаются), «Избирательно» (слияние + mergetool).
8. **`.obsidian\` хранится в git** (решение пользователя); `remotely-save\main.js` исключён —
   GitHub Push Protection находил в нём Google OAuth ключи автора плагина (это и был «бесконечный
   пуш»).
9. **Яндекс Диск** 27.09 откатил папку alpha (старые версии под основными именами, новые — копиями
   « (2)», включая `.git`). Решено: из Яндекс Диска не переносим; при сбое восстанавливаем из git
   и чистим копии (так восстановлен коммит `79d072f` д2).
10. **Перенос в Beta** — `git push origin alpha/Mzs7:Beta` без force-push, после проверки
    `git log origin/alpha/Mzs7..origin/Beta` (пусто). Так `reset --hard` больше не сотрёт коммиты
    Beta (23.09 так потерялась функция первого запуска).

## Что открыто

1. Закоммитить и отправить состояние диска (тег `0.0,0.0,0.0,3`), затем обновить Beta. При
   обновлении Beta перенести её `Сам проект\Save\` (config, state, журналы — не в git) в
   `Сам_проект\Save\`, иначе Beta запустится как в первый раз; поправить ярлык на `AutoSync.pyw`.
2. Посмотреть новые окна выбора вживую в Beta и через день работы проверить журнал Beta.
3. Объём замены названий на Git_Avto: тексты; файлы программы (`AutoSync.pyw`, `autosync.log`);
   папка `.autosync_data` в отслеживаемых проектах; репозиторий и папка.
4. Лог на каждый запуск — по образцу Godot_Template (`Сообщения\Ответ_IT_логи.md`), детали не
   решены.
5. Перенос кода в структуру Оператора_Проводника — после решений координатора.
6. Нет автоматического `git init` при отсутствии `.git` — идея на будущее.
