# Ответ на «Вопрос_IT_логи_26.09.md» — как устроено логирование в Godot_Template

От: чат Project «IT» (claude.ai), 26.09.2026. Источник — `Class_Logger.gd` и
`План_проекта/Документы/Классы/Class_Logger.md` в репозитории Godot_Template.

1. **Где лежат и как называются.** Папка `res://Save/Logger/Logs/`. Имя файла:
   `Logger_<роль>_<дата>_<время>.log`, например `Logger_user_2026-08-25_13-05-44.log`. Роль —
   `"user"`/`"server"`/`"test"`, передаётся в `fxG_StartingLogger_CrTr(vGS_Role)`; дата/время —
   момент старта программы.
2. **Новый файл на каждый запуск.** Да — один файл на сессию (на один запуск программы), не по
   дням и не по размеру.
3. **Хранение и очистка старых.** Три независимых лимита, каждый со своим флагом
   вкл/выкл, читаются из `Save/Settings.json` (ключи `LogMaxCount*`, `LogMaxAge*`,
   `LogMaxSize*`), значения по умолчанию — в самом классе:
   - по количеству файлов (`vGI_LogMaxCount`, по умолчанию 100);
   - по возрасту в днях (`vGI_MaxLogAgeDays`, по умолчанию 30);
   - по суммарному объёму папки в МБ (`vGI_MaxLogFolderSizeMb`, по умолчанию 50).
   Чистка идёт по шагам в этом порядке (возраст → количество → объём), каждый следующий шаг
   работает с тем, что осталось после предыдущего; отключённый флаг шаг пропускает.
4. **Формат строки и уровни.** Уровней INFO/WARN/ERROR нет — запись всегда 4 поля:
   `[Время_мкс_от_старта_движка, Код, Значения, Другое]`, где «Код» — произвольная строка на
   английском («точка в коде», например `"if A and B"` или `"func A(A, B, C)"`), «Значения» —
   массив переменных к этой точке, «Другое» — доп. информация (например, результат `if`) или
   `null`. Записи группируются не по уровню важности, а по **потокам** (`Streams`) — независимым
   цепочкам событий (экран, загрузка, фоновая операция), у каждого потока свой `StreamId` и
   список записей; в файле это `{"Streams": {StreamId: [запись, ...]}}`.
5. **Отдельный лог ошибок/крашей.** Отдельного файла нет. Вместо этого — реестр
   `Save/Logger/Straming_path.json`: при старте проверяется, какие потоки остались `active`
   (не закрыты вызовом `fC_FinishStream_Ch`) — если такие есть, это след краша, и они дописываются
   как незавершённые в **старый** файл лога той сессии, после чего реестр очищается для новой
   сессии.
6. **Что видно в интерфейсе.** В самом классе UI не описан (это делает вызывающая сторона —
   `Сцена Start_Program`); логгер — просто источник данных.
7. **Путь к файлу.** `res://Godot_Template/Class_Logger.gd` в репозитории Godot_Template
   (документация класса — `План_проекта/Документы/Классы/Class_Logger.md`).

Для сравнения с текущим состоянием AutoSync (общий `autosync.log` + `autosync_crash.log`,
хвост в окне): здесь принципиально другая модель — не единый постоянный файл с уровнями и не
отдельный crash-лог, а файл на сессию + реестр незавершённых потоков, который сам находит
крash-хвосты при следующем запуске. Если для AutoSync нужен именно такой перенос (файл на
сессию + потоки), это отдельное решение — сообщите, что для AutoSync предпочтительнее, и можно
расписать план переноса подробнее.

Известные ограничения самого Class_Logger (на случай, если пригодится): сброс по таймеру
(`TimeUpdate`) не подключён — только по счётчику записей (`FrequencyUpdates`, по умолчанию 10);
при падении программы могут не попасть на диск до 9 последних записей каждого потока.
