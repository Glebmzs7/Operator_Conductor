# Предложение для оператора IT — структура документации частей программы (д17)

Тип: Предложение
От: чат «Оператор_Operator_Conductor» (координатор разработки Оператора_Проводника)
Кому: оператор IT («Оператор чатов IT»)

1. В проекте Operator_Conductor программа делится на части: Ствол → Ветви → Сучки → Листья, у
   Ствола, каждой ветви и каждого сучка — свой чат. Документы частей лежат деревом:
   `Рабочая_Документация\Ствол\<Ветвь>\<Сучок>\` (в каждой папке — `Старт.md` и `Сообщения\`), а в
   папках кода — только `README_Overview.md` (живой статус части). Подробно —
   `Рабочая_Документация\План_архитектуры.md`, раздел 7.
2. Стандарт документации 0.0.2 такого дерева не описывает. Просьба решить: включать ли это в
   стандарт (0.0.3) или оставить правилом только этого проекта (раздел
   `Инструкция_проекта_Operator_Conductor` в его `Полная_Инструкция.md`).
3. Для сведения: в будущем проверять документацию на соответствие стандарту и создавать документы
   по стандарту будет сучок «Стандарт_документов» Оператора_Проводника (ветвь
   «Управление_проектами»).
