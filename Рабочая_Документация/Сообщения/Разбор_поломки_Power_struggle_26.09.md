# Разбор поломки Power_struggle 25.09 — для чата GIT_Automation

От: чат Project «IT» (claude.ai), 26.09.2026 — тема «Уточнения файлов от проектов». Пересылается
пользователем в чат GIT_Automation как есть, с доказательствами.

## Суть

В 19:41 25.09 GIT_Automation выполнил `git checkout alpha/Mzs7` в рамках автоматического
переключения на отслеживаемую ветку. Локальная ветка `alpha/Mzs7` в этот момент была устаревшей —
указывала на коммит `c06fb2d` (структуру ДО переноса `.git` в этом же репозитории накануне),
тогда как `main` уже был на правильном `0757e78`. Переключение без проверки «отстаёт/не отстаёт»
подменило рабочее дерево на старое, и следующий пуш (ручное изменение версии) закрепил это
состояние на GitHub.

   e774a76 HEAD@{1}: commit: Ручное обновление версии: 0.0,0.0,0.0,0

3. `Class_Watcher.py`, комментарий у места, где это переключение происходит: «...теперь (по

4. `git show 0757e78 --stat` подтверждает, что именно этот коммит содержит полную структуру

   поломка случилась именно на шаге переключения ветки, не раньше.

## Предложение на review

Перед автоматическим `git checkout <ветка>` в отслеживаемую ветку — сверять, не старше ли она
текущего HEAD (по `git merge-base`/`git log <ветка>..HEAD`), и если переключение фактически
откатывает файлы назад — не делать это молча, а спросить (`ask_yes_no`) с показом, что именно
откатится.

## Статус восстановления Power_struggle (на момент этой записи)

Восстановление начато в чате Project «IT» 26.09 (см. `git reflog`/`git show` выше) — коммит
`0757e78` найден и подтверждён рабочим, `git branch -f alpha/Mzs7 0757e78` не сработал (ветка
занята текущим worktree), вместо него используется `git reset --hard 0757e78` прямо на
checked-out ветке `alpha/Mzs7`, затем `git push --force-with-lease origin alpha/Mzs7`.
