## Что это

Python-программа (Tkinter GUI, без консоли — запускается через `AutoSync.pyw`) для автоматической
git-синхронизации: следит за файлами одного или нескольких репозиториев, коммитит и пушит
изменения без участия пользователя, спрашивает подтверждение только при расхождениях/конфликтах.
Версионирование — через git-теги (свободный текстовый префикс + номер пуша, который считает сама
программа), автоподбор свободного номера при коллизии, атомарный пуш ветки+тега.

## Структура кода

- `Class/` — код программы:
  - `Class_Watcher.py` — основная логика демона (слежение, СВЕРКА_ВЕРСИЙ, коммит/пуш, разрешение
    конфликтов, add/edit/delete/toggle репозитория из окна, `main()`)
  - `Class_Gui.py` — интерфейс (окно, диалоги, журнал событий внизу окна, обработка ошибок
    Tkinter-колбэков); `_open_add_dialog` — окно добавления репозитория (кнопка "+")
  - `Class_GitOps.py` — обёртка над git-командами (fetch, commit, push, tag и т.д.)
  - `Class_Version.py` — разбор/сборка версии-тега (префикс + номер пуша, разделитель любой)
  - `Class_RepoData.py` — копия данных репозитория (`.autosync_data`) внутри папки самого
    проекта — чтобы данные переезжали вместе с папкой **в пределах одного ПК** (перемещение
    папки, отключение/повторное подключение в AutoSync). Через git не передаётся —
    `/.autosync_data/` в `.gitignore` намеренно (решение 25.09).
  - `Class_SelfUpdate.py` — самообновление самой программы AutoSync
  - `Class_State.py` — хранение `known_version` между запусками
- `Save/` — данные: `config.json` (настройки/список репозиториев), `state.json`,
  `update_branch.txt`, логи (`autosync.log`, `autosync_crash.log` — рабочие файлы программы,
  не трогать), `config.example.json` — образец формата.

## Причины "потерянных правок" и зависаний (установлено 26.09)

1. `reset --hard Beta` на alpha 23.09 стёр Beta-коммиты `c988ee5` (первый запуск) и `7ead83d`.
2. **Взаимная блокировка (главная причина зависаний):** `RepoWatcher._lock` был обычным
   `threading.Lock`, а `sverka_versiy` вызывает сама себя, держа его (после «синхронизировано»,
   после выбора в диалоге расхождения, после повтора при ошибке связи). Поток ждал сам себя
   вечно — репозиторий вставал после первого же успешного пуша. GIT_Automation: успешный пуш
   25.09 20:44 → дальше только «Плановая проверка...» до перезапуска 26.09 14:37; Power_struggle —
   после force-push 25.09 19:41. Исправлено: RLock.
3. Отклонённый пуш оставлял локальный коммит, а следующие проверки говорили «пуш не нужен»
   (смотрели только незакоммиченные изменения). Исправлено: коммиты впереди origin отправляются.

## Баги Beta (26.09)

1. Бесконечный пуш — любая ошибка push считалась занятым тегом (50 повторов, текст ошибки не
   писался). Исправлено: ошибка всегда в журнале; +1 к номеру только если тег реально есть на git;
   тег только на компьютере — «Проблема», номер не двигаем; обрыв связи — 3 повтора того же тега
   (пауза 10 с); прочее — «Проблема» без повторов. Причина отказа GitHub для `f7ff025` ещё
   неизвестна — увидим в журнале после обновления.
2. Зависание проверок — см. п. 2 причин; плюс диагностика: занятая проверка пишет «Проверка
   пропущена: идёт с ЧЧ:ММ:СС, этап — …»; >10 мин (не ожидание ответа) → «Проблема».
3. **Баг программы: автопереключение ветки откатывает файлы** (источник — чат IT,
   `Разбор_поломки_Power_struggle_26.09.md`). `_action_push`: если на диске переключена не та
   ветка, AutoSync молча делает `git checkout <отслеживаемая ветка>`, не проверяя, не устарела ли
   она. 25.09 19:41 у Power_struggle локальная `alpha/Mzs7` указывала на старый `c06fb2d`, а работа
   была на `main` (`0757e78`) — checkout откатил рабочее дерево, следующий пуш закрепил откат на
   GitHub. Виновата программа. Восстановление Power_struggle делает чат IT.
   Варианты решения:
   - А. Перед checkout проверять `git log --oneline <ветка>..HEAD`; пусто — переключать как
     раньше; есть коммиты — не переключать, «Проблема» со списком коммитов.
   - Б. То же, но вместо «Проблемы» — окно выбора с двумя кнопками, на кнопках теги:
     «Остаться на <текущая> — <тег>+» / «Переключиться на <ветка> — <тег>+» («+» — есть изменения
     поверх тега). Пользователь 26.09 попросил теги и «+» на кнопках выбора — см. задачу в чате.
   - В. Не переключать никогда автоматически — только сообщать (как было до 22.09).

4. **GitHub Push Protection** (найдено 26.09 по ручному push): коммит `f7ff025` отклонён — в
   `.obsidian/plugins/remotely-save/main.js:90` GitHub нашёл Google OAuth Client ID и Client
   Secret (зашиты в код плагина remotely-save). Это и была причина «бесконечного пуша»: отказ по
   существу, повтор не поможет. Решение за пользователем: разрешить секрет по ссылке GitHub или
   не хранить `main.js` плагинов в git (коммит `f7ff025` ещё не на сервере — можно переделать).
   Вероятно, та же причина у Godot_Template 26.09 13:27.

## Архитектурное решение (24.09): обмен файлами шаблона между проектами

Для переноса общих файлов из `Godot_Template` в `Life_Operator`/`Power_struggle` выбран
**git subtree** (не submodule): обычные отслеживаемые файлы, ложится на модель AutoSync
(`git add .` + commit + push). Пересекается с запланированной функцией AutoSync "второе
слежение" — реконсиляция `Godot_Template_<Проект>` с автопрокидыванием изменений обратно в
`Godot_Template`; subtree-перенос имеет смысл делать частью этой функции.

## План

1. Пользователь вручную пушит alpha (коммит `f7ff025` + первый запуск) и присылает текст ошибки,
   если GitHub откажет.
2. Исправить в alpha: логирование текста ошибки push и остановка повторов при отказе не из-за
   тега; диагностика зависания проверок; лог на каждый запуск.
3. Проверить в git построчным поиском нужных строк.
4. Перенос в Beta: `git fetch origin; git checkout Beta; git reset --hard origin/alpha/Mzs7;
   git push --force origin Beta` — перед этим убедиться, что в Beta нет своих коммитов, которых
   нет в alpha (`git log origin/alpha/Mzs7..origin/Beta`), иначе они снова потеряются.
