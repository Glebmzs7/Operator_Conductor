# План архитектуры — Оператор_Проводника (Operator_Conductor)

Тип: план (рабочая документация проекта Operator_Conductor)
Составлен: 17.10.2026, чат Project «Оператор чатов Claude», по решениям пользователя.
Переработан: д15, координатор «Оператор_Operator_Conductor» (система «Ствол — Ветви — Сучки —
Листья», ответы пользователя на открытые вопросы, новые сучки).
Ведёт: чат-координатор «Оператор_Operator_Conductor».

## 1. Что это

Одна фоновая программа для работы с файлами в `Проекты\` (и в любых других папках из настроек).
Вырастает из Git_Avto (прежние названия — GIT_Automation, AutoSync). Объединяет:

- Git_Avto (нынешний код `Сам_проект\Class\`);
- `Проекты\Claude\Замена_пробелов.py` → Массовая_Переименования;
- `Проекты\Claude\Шаблоны\Создание_проекта.pyw` → Создание_проектов;
- новое: журнал фиксаций, Версии_файлов, Облачная_Синхронизация, Стандарт_документов,
  Сборка_файлов_из_частей, Ссылки_в_Проводнике, Распознавание_текста.

Платформы: сейчас Windows; Linux — следующая; Android и iPhone — пока в планах. При любом выборе
учитывается будущий перенос: логика отделена от интерфейса и от Windows.

## 2. Устройство: Ствол — Ветви — Сучки — Листья

1. **Ствол** — то, что нужно всем ветвям: наблюдение за папками и процессами, инструменты
   изменения файлов, настройки, окно, загрузчик.
2. **Ветвь** — набор инструментов под один вид задач (например, Синхронизация — бэкенды: сеть,
   аккаунты, передача файлов, сравнение версий, конфликты).
3. **Сучок** — отдельное расширение под конкретную задачу на инструментах своей ветви (например,
   Git_Avto).
4. **Лист** — часть сучка или ветви. Пользователь может подключать свои листья: скриптом на Python
   и настройкой из готовых частей без кода — в любую точку, которую ветвь или сучок объявили.

**Правило зависимостей.** Код пользуется только тем, что ниже (лист → сучок → ветвь → Ствол).
Младшие части не используются в работе старших: Ствол не знает конкретных ветвей и сучков и
работает с ними только через договор. Информация вверх идёт через договор Ствола — события, журнал,
вкладка в окне. Сучок не обращается к соседнему сучку; инструмент, нужный двум ветвям, переносится в
Ствол.

```
Ствол
├─ Синхронизация (бэкенды)
│    ├─ Git_Avto
│    └─ Облачная_Синхронизация
├─ Управление_проектами
│    ├─ Создание_проектов
│    ├─ Стандарт_документов
│    └─ Сборка_файлов_из_частей
└─ Работа_с_файлами
     ├─ Массовая_Переименования
     ├─ Версии_файлов
     ├─ Ссылки_в_Проводнике
     └─ Распознавание_текста
```

## 3. Ствол

- Запуск в фоне, значок у часов (трей), автозапуск вместе с системой.
- **Два режима** (выбор в настройках): постоянный — всё время следит за папками; по кнопке —
  слежения нет, проверка запускается вручную (для слабых устройств).
- Один общий наблюдатель за папками (watchdog), события раздаются ветвям и сучкам. Своих
  наблюдателей у них нет.
- Наблюдение за процессами, «кто изменил» — журнал аудита Windows, событие 4663 (`os_layer\`).
- **Журнал фиксаций** (раздел 3.1).
- **Инструменты изменения файлов**: переименовать, переместить, записать; проверить, не занят ли
  файл; хэш. Изменения через них сами попадают в журнал фиксаций.
- Один файл настроек `Save\config.json` с разделом на каждую ветвь и сучок; папки для слежения;
  **список проектов** с настройками каждого (какие сучки и листья включены).
- **Загрузчик** ветвей, сучков и листьев (оба вида листьев).
- Окно на **PySide6**: трей, вкладки — по вкладке на ветвь/сучок.
- Общий журнал программы (лог на каждый запуск).

### 3.1. Журнал фиксаций

- Формат: `.csv`, файл на месяц: `Журнал\2026-10.csv`.
- Поля строки: время, действие (создан / изменён / удалён / перемещён / скопирован), путь,
  новый путь, процесс, пользователь, размер, хэш содержимого, номер версии.
- «Кто изменил» (процесс и пользователь) — из журнала аудита Windows, событие 4663.
- Копия распознаётся по хэшу: новый файл с хэшем уже существующего → «скопирован из …».
- Номер версии выдаёт сучок Версии_файлов (если включён).

### 3.2. Шаги пользователя под администратором (только Windows, один раз)

Программа и Claude системные настройки не меняют — пользователь делает сам по инструкции (пишет
чат Ствола):

1. Включить аудит подкатегории «Файловая система».
2. Добавить правило аудита (SACL) на папку `Проекты`.
3. Добавить своего пользователя в группу «Читатели журнала событий».
4. Увеличить размер журнала «Безопасность».

## 4. Ветвь «Синхронизация» (бэкенды)

Инструменты ветви: сеть и порты, вход в аккаунты, передача файлов, сравнение версий, конфликты.

### 4.1. Git_Avto

Код нынешнего `Сам_проект\Class\`: коммит и пуш по настройкам репозиториев. Переписывается на
договор Ствола после того, как Ствол готов. События берёт у Ствола. Формат настроек (repos,
watch_paths, ignored_folders и т.д.) переносится в общий `config.json`. До готовности Ствола Beta
работает на старом коде, старый код не меняется.

### 4.2. Облачная_Синхронизация

Работа с облачными хранилищами: подключать существующие или развернуть своё, настраивать, какие
файлы и зачем отслеживать. Порядок: сначала Яндекс Диск; затем, вероятно, своё хранилище; позже
Google Drive и другие. Опыт проекта: Яндекс Диск 27.09 откатывал файлы и `.git` (копии « (2)») —
сучку стоит уметь находить такие копии и предупреждать.

## 5. Ветвь «Управление_проектами»

Инструмент ветви: «шаблон документа» — общий для Создания_проектов и Стандарта_документов.

### 5.1. Создание_проектов (было Шаблоны_Проводника)

- Код Создание_проекта: шаблон + `Правила_замены.json`, действия поле / текст / дата / код / после,
  CLI-режим.
- Пункт контекстного меню Проводника «Создать проект из шаблона» — одобрен в целом. Делается
  записью в реестр текущего пользователя (`os_layer\`), удаляется кнопкой в настройках.

### 5.2. Стандарт_документов

Проверяет документацию проекта на соответствие стандарту и создаёт документы по стандарту.

### 5.3. Сборка_файлов_из_частей

Собирать файл из частей — сначала `Полная_Инструкция.md`: склеить мастер + правила отрасли
(+ правила проекта), подписать разделы днём изменения (`от_д<N>`), разложить сборки по папкам и
пересобирать при изменении любой части (по событиям Ствола). Пока сборки делают чаты вручную,
автоматический запуск — позже.

## 6. Ветвь «Работа_с_файлами»

Инструменты ветви: обход дерева папок, таблица переименований, поиск путей в тексте, ярлыки.

### 6.1. Массовая_Переименования

Приведение имён к **Стандарт_Названий**. Наборы правил создаются и сохраняются в настройках
программы под своими именами.

Настройки набора:

- Разделение слов (выбор одного): пробел / заглавная буква («СловоСлово») / нижнее подчёркивание /
  тире.
- Язык имён: только английский / только выбранный язык (любой из Unicode).
- Галочка про цифровые названия: файлы, имя которых состоит только из цифр и символов (например
  `1.md` в Фиксации), — оставить как есть или сообщить, что их нужно изменить.
- Галочка: менять ли пути внутри файлов (как в Замена_пробелов: только в контексте пути).
- Галочка: что переименовывать — папки / файлы.

Порядок работы:

1. Формируется список нужных изменений в виде дерева.
2. Сверка с таблицей прошлых переименований: если у файла уже были такие же настройки — берётся
   прошлое имя.
3. Дерево показывается пользователю; проверяется, что файлы сейчас можно изменить (не заняты).
   Дальше — только после подтверждения.
4. Переименование от самых глубоких к корню. Каждое изменение записывается в таблицу
   переименований — по ней работает «Откатить».

### 6.2. Версии_файлов (свой «гит» внутри программы)

Фиксации — скелет (Ствол), версии — мышцы (этот сучок). Каждое изменение получает номер версии.

- Текстовые файлы: **исходный файл + цепочка изменений + полная последняя версия**. Восстановить
  можно вперёд от исходного и назад от последней.
- Двоичные файлы: целая сжатая копия каждой версии, одинаковые копии хранятся один раз. Галочка —
  версионировать ли двоичные файлы вообще.
- Хранилище по умолчанию — там же, где программа; путь меняется в настройках.
- Очистка (каждая включается отдельно, можно несколько): по времени, по объёму, по количеству.
- Галочка «удалять исходную версию при очистке»: точка восстановления **сдвигается** на следующую
  версию. **Нельзя удалить версию, если после этого не останется точки, от которой можно
  восстановить** оставшиеся.
- Ограничение размера файла — настройка (по умолчанию без ограничения).
- Исключения — отдельный список в папке настроек; содержание согласуется позже.
- Восстановление — из окна: файл → список версий → «Восстановить».

### 6.3. Ссылки_в_Проводнике

Ярлыки Windows и ссылки внутри файлов ломаются при переименовании и перемещении. Реестр ссылок
(ярлыки и ссылки в файлах): один раз указать правильную цель и править её в одном месте —
программа обновляет все ярлыки и ссылки. Обновление — по событиям «переименован / перемещён» от
Ствола (в том числе от Массовой_Переименования). Ярлыки .lnk — через `os_layer\`.

### 6.4. Распознавание_текста

Общий инструмент для всех проектов:

1. Открыть фото или скан.
2. Поставить 4 угла листа вручную.
3. Выпрямить перспективу и, при необходимости, поворот (OpenCV).
4. Распознать текст через Tesseract (русский + английский).
5. Сохранить текст (`.md` / `.txt`) или PDF с текстовым слоем.

Почему своё: PowerToys Text Extractor такого не умеет, OCRmyPDF выравнивает только автоматически.
Инструменты и команды установки — `Проекты\Наука\Claude\Уведомление_Распознавание_текста_17.10.md`
(копия — в `Исходники\` сучка).

## 8. Чаты и порядок работ

- Чаты: координатор, Ствол, по чату на каждую ветвь (3) и на каждый сучок (9). Запускаются по
  очереди, не все сразу.
- Каждый чат меняет только свои папки (раздел 7). Репозиторий общий (`alpha/Mzs7`); пока чат
  Git_Avto на паузе, коммит и пуш делает пользователь по командам чатов.
- Порядок: **Ствол** (договор, каркас, наблюдатель, журнал фиксаций, инструменты файлов) →
  **Git_Avto** (переписка на договор; после этого Beta переходит на новый код) → остальные ветви и
  сучки в порядке, который координатор согласует с пользователем.
- Решения, требующие пользователя, — через координатора.
